# Trade History Analysis

**체결 내역은 "무엇을 했는지"만 담고 "왜 했는지"는 담지 않는다.** 그래서 이 분석으로
얻을 수 있는 것은 **구조**(얼마나 크게, 몇 번에 나눠, 얼마나 오래, 어떤 주문으로)이고,
**판단**(언제 어느 방향으로)은 대부분 얻지 못한다. 이 스킬의 결론은 거의 항상 "구조는
옮기고 판단은 따로 검증한다"이다. 이 구분을 흐리는 것이 가장 비싼 실패다 — 남의 수익
곡선을 보고 내 진입 규칙을 고르게 된다.

두 번째 원칙: **수익률이 아니라 생존 방식을 본다.** 공개된 고수익 계좌는 생존자다. 같은
방식으로 매매하다 사라진 계좌는 공개되지 않는다. 그 계좌가 *어떻게 안 죽었는지*(노출,
손실 처리, 레버리지 변화)가 *얼마를 벌었는지*보다 옮길 가치가 크다.

## 0. 순서

```
1. 정규화 → 2. 트레이드 재구성 → 3. 원장 대조 → 4. 행동 지표 → 5. 이식 판정
```

3번을 건너뛰면 재구성 버그를 그 사람의 매매 습관으로 읽는다.

## 1. 정규화 — 어떤 데이터인지 먼저 확인

| 확인 | 왜 |
|---|---|
| **체결 단위인가, 주문 단위인가** | 주문 단위(평균가·총체결수량)면 분할 체결·체결 시각을 모른다. 보유시간은 주문 시각 기준 근사다 |
| **시각이 체결 시각인가, 주문 시각인가** | 지정가를 오래 걸어두는 사람이면 주문 시각과 체결 시각 차이가 크다 |
| **수동인가, API인가** | 주문 출처 필드(BitMEX `text`, 증권사 매체구분)를 본다. 수동이면 "규칙"이 없을 수 있다 |
| **손익 통화와 계약 종류** | 인버스(코인 마진)·쿼토·선형이 섞이면 가격×수량으로 손익을 못 낸다 → `references/crypto.md` |
| **비용이 행에 있는가** | 국내주식은 수수료·거래세가 체결 행에 없는 경우가 많다 → `references/krx.md` |
| **펀딩·배당·이자·입출금** | 트레이드 손익과 분리해서 따로 합산한다. 섞으면 자산 곡선이 손익처럼 보인다 |

`scripts/reconstruct_trades.py`가 세 형식을 읽는다: `generic`(time, symbol, side, qty,
price + 선택 열), `bitmex`, `kis`(한국투자증권 `inquire-daily-ccld` output1).

## 2. 트레이드 재구성 — 포지션 0→0

심볼별 순포지션이 0에서 출발해 0으로 돌아오는 구간을 트레이드 1건으로 본다. 한 체결
안에서 부호가 뒤집히면(롱 → 숏) 비율로 나눠 앞 트레이드를 닫고 새 트레이드를 연다.

```bash
python scripts/reconstruct_trades.py fills.csv --format generic --equity equity.csv --out out/
```

- **손익 = −Σ 현금흐름 − Σ 비용.** 가격으로 다시 계산하지 않는다. 계약마다 부호와
  단위가 다르다.
- **미청산 트레이드는 집계에서 뺀다.** 마지막 포지션 하나가 수년치 손익과 맞먹을 수 있다.
- `--equity`(일별 자산)가 있으면 **노출 배수**(트레이드 중 최대 진입명목 ÷ 전일 자산)와
  **%자산 손익**을 낸다. 자산 없이 절대 손익만 보면 계좌가 커진 뒤의 트레이드가 결론을
  지배한다.

## 3. 원장 대조 — 재구성이 맞는지

재구성 손익 합계를 원장(지갑 실현손익, 증권사 기간손익) 합계와 **심볼별로** 맞춘다.
`--ledger-total`을 주면 요약에 차이를 찍는다.

차이가 나면 이 순서로 본다: 펀딩/배당 → 미청산 포지션(거래소는 일부 청산 때마다
실현손익을 잡는다) → 만기 정산·기업행위 → 수수료 부호. 심볼 하나라도 설명 안 되는 차이가
남으면 4번으로 가지 않는다.

## 4. 행동 지표 — 무엇을 재는가

**연도별로 나눠서 본다.** 같은 사람도 해마다 다른 트레이더다. 전 기간 평균은 초기의
고레버리지 구간과 후기의 저레버리지 구간을 섞어 아무도 아닌 사람을 만든다.

| 지표 | 질문 | 해석 함정 |
|---|---|---|
| 노출 배수 (중앙값·p90) | 계좌 대비 얼마나 크게 들어가나 | **연도별 변화**가 핵심이다. 줄었다면 언제, 무슨 일 뒤에 |
| 최악 트레이드 %자산 | 한 번에 얼마까지 잃었나 | 하루 −50% 같은 값이 있으면 그 전후로 구간을 나눈다 |
| 승률 · payoff · PF | 어떤 수익 구조인가 | 승률이 높고 payoff < 1이면 **손실을 오래 들고 있는 구조**일 가능성이 크다 |
| 보유시간 수익 vs 손실 | 손실을 빨리 자르나 | 손실 > 수익이면 물타기·버티기. 저노출 없이 따라 하면 위험하다 |
| 진입/청산 주문 수 | 분할하나 | 큰 계좌는 체결 충격 때문에 쪼갠다. 작은 계좌는 최소 주문 단위가 막는다 |
| avg_down% | 불리하게 추가 진입하나 | 물타기 비율이 높고 손절 주문이 거의 없으면 리스크는 **노출 크기**로 관리한 것이다 |
| maker% / limit% | 어떤 주문으로 들어가나 | 코인은 maker 리베이트가 손익에 직접 영향. KRX는 maker 개념이 없다 |
| 롱/숏 비율 | 방향 편향 | 상승장 구간의 롱 편향은 습관이 아니라 시장이다 |
| 보유시간 구간별 순손익 | 돈이 어디서 나오나 | 건수가 많은 구간과 돈이 나오는 구간이 다른 경우가 흔하다 |
| 상위 5% 트레이드 비중 | 소수 트레이드 의존도 | 100% 넘으면 나머지 전체는 손실이다. 그 소수를 놓치는 시스템은 다른 결과를 낸다 |

**진입 맥락**(진입 직전 N시간 수익률, RSI, 이평 대비 위치)은 체결 내역만으로 못 낸다.
**실제 시세 캔들**이 따로 필요하다. 체결가로 만든 캔들은 그 사람이 거래한 시간만 채워져서
지표가 왜곡된다 — 진입 시점이 "변동성이 높을 때"로 보이는 건 체결이 있는 시간만 가격이
움직이기 때문이다.

## 5. 이식 판정 — 무엇을 옮기나

| 구분 | 예 | 판정 |
|---|---|---|
| **구조 — 옮길 수 있다** | 계좌 단위 노출 상한, 지정가 진입, 분할 청산, 종목 집중, 고점 대비 낙폭 정지 | 규칙으로 바로 쓴다. 엣지가 없어도 손실 분포를 바꾼다 |
| **조건부 — 전제가 있어야** | 물타기, 손절 없는 보유, 역추세 진입 | 원본의 전제(낮은 노출, 재량적 포기 판단)를 같이 옮길 수 있을 때만. 아니면 위험이 커진다 |
| **판단 — 옮길 수 없다** | 진입 방향·타이밍 | 지표로 방향을 맞히는 모델의 AUC가 0.6 미만이면 "재량"으로 결론 내린다. 비슷한 경향(예: 상승 추세 속 눌림 매수)이 보이면 **가설**로만 쓰고 shadow로 검증한다 |

판정 산출물에는 반드시 세 가지를 쓴다.

1. **원본의 전제** — 그 방식이 통한 조건(노출, 계좌 크기, 시장, 기간)
2. **내 시스템과의 차이** — 같은 지표를 내 체결내역으로 돌린 값을 옆에 놓는다
3. **검증 방법** — 실거래 투입 전 shadow/paper로 몇 건, 어떤 지표로 확인할지

### 내 수동매매를 시스템화할 때

같은 분석을 **내 체결내역**에 돌린다. 이때가 이 스킬이 가장 쓸모 있는 경우다 — 남의
판단은 못 옮겨도 내 판단은 왜 그랬는지 물어볼 사람이 있다.

- 수익 트레이드와 손실 트레이드를 나눠 보유시간·분할 횟수·물타기 비율을 비교한다.
  차이가 큰 항목이 규칙 후보다 (예: "손실 트레이드만 3번 이상 추가매수" → 추가매수 상한).
- 최악 10건을 날짜와 함께 뽑아 **그때 무엇을 보고 들어갔는지** 사용자에게 묻는다.
  답이 일관되면 진입 규칙 후보, 일관되지 않으면 재량이다.
- 규칙은 손실을 줄이는 쪽(노출·추가매수·보유시간 상한)부터 만든다. 진입 규칙보다
  검증이 쉽고 효과가 바로 보인다.

## 검수 체크리스트

- [ ] 데이터가 체결 단위인지 주문 단위인지, 시각이 무엇인지 적었는가
- [ ] 재구성 합계를 원장과 심볼별로 대조했는가. 차이를 설명했는가
- [ ] 미청산 트레이드를 집계에서 뺐는가
- [ ] 비용(수수료·세금·펀딩)을 넣은 net인가. 빠졌으면 "gross"라고 표시했는가
- [ ] 지표를 연도별로 나눴는가. 레버리지가 바뀐 시점을 찾았는가
- [ ] 진입 맥락을 체결가 캔들로 계산하지 않았는가
- [ ] 결론을 구조 / 조건부 / 판단으로 나눴는가
- [ ] 추정한 값과 실측한 값을 구분해 표시했는가

## 하지 말 것

- 남의 수익률을 내 시스템의 목표치로 쓰지 않는다. 생존자다.
- 재량 매매 내역에서 진입 규칙을 "추출"했다고 주장하지 않는다. AUC를 같이 적는다.
- 물타기·무손절을 노출 상한 없이 옮기지 않는다.
- 전 기간 평균 하나로 그 사람을 요약하지 않는다.
- 체결가로 만든 캔들로 진입 맥락을 계산하지 않는다.
- 공개 레포·문서에 계좌번호, 개인 잔고, 앱키를 남기지 않는다.
