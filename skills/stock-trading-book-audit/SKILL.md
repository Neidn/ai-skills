# Stock Trading Book Audit

**증권사 원장이 진실이고, 내 DB는 주장이다.** 원칙은 `trading-book-audit`(코인)와 같다.
실거래 시스템은 틀린 숫자를 경고 없이 오래 보고하고, 그 숫자를 읽는 사이징·리스크
가드도 같이 틀린다. 이 스킬은 그 원칙을 국내주식에 옮기고, **주식에만 있는 함정**을
더한다. 주식에만 있는 함정은 다음과 같다. 매도 시 거래세가 붙고, 기업행위가 가격을
불연속으로 바꾸며, 장이 닫혀 있는 동안 갭이 생기고, 손절이 거래소가 아니라 내 프로세스에
있다.

두 번째 원칙: **표본이 결론을 못 낼 크기면, 결론을 내지 않는다.** 주식 스윙 봇은
매매 빈도가 낮다. N=50이 석 달일 수 있다는 사실을 먼저 말한다.

## 0. 순서를 지킨다

```
1. 원장 확보 (증권사 체결내역·잔고)  →  2. 필드 신뢰성 감사  →  3. 그다음에야 성과 판정
```

2번을 건너뛰면 버그를 전략 탓으로 돌린다. 특히 주식에서는 **기업행위 하루가 한 달
성과를 뒤집는다.** 배당락·분할일에 찍힌 "손실"이 진짜인지부터 본다.

## 1. 원장 확보 — 무엇이 ground truth인가

| 질문 | 근거로 쓸 것 | 쓰면 안 되는 것 |
|---|---|---|
| 실제로 얼마 벌었나 | 증권사 **일별 체결내역**(체결가·수량·수수료·제세금) | 내 DB의 `realized_pnl` |
| 지금 뭘 들고 있나 | 증권사 **잔고 조회** | 로컬 포지션 테이블 |
| 계좌가 늘었나 | 예수금 + 평가금액, 입출금 분리 | 잔고 곡선 그대로 (입금이 수익처럼 보인다) |
| 배당은 얼마 받았나 | 입출금/배당 입금 내역 | 가격 변화 (배당락은 손실처럼 보인다) |

**net = 매도대금 − 매수대금 − 매수수수료 − 매도수수료 − 거래세(+농특세) + 배당(세후).**
이 중 하나라도 빠진 숫자는 손익이 아니다.

- **세율·수수료율은 기억으로 쓰지 않는다.** 거래세는 시장(KOSPI/KOSDAQ/코넥스)마다
  다르고 거의 매년 바뀐다. 산출물에 **적용 세율과 조회일**을 적는다. 기간이 세율
  변경일(보통 1월 1일)을 걸치면 **구간을 나눠서** 적용한다.
- **증권사 앱의 "실현손익"이 무엇을 뺀 값인지 확인한다.** 수수료·세금 차감 여부와
  평균단가 방식이 증권사마다 다르다. 확인 전에는 대조용으로만 쓴다.
- 매매당 비용(왕복 수수료 + 거래세)이 gross edge의 큰 비중(예: 30% 이상)이면
  그 "엣지"가 비용에 먹히는 노이즈가 아닌지 먼저 배제한다. 거래세는 **매도금액에
  비례**하므로 회전율이 높은 단타 전략일수록 치명적이다.

`references/queries.md` — 체결내역 대조, 비용 분해, 전략별 net, 기업행위 탐지 쿼리.

## 2. 필드 신뢰성 감사 — 리포터가 아니라 소비자를 찾아라

손익 컬럼이 의심스러우면 **그 컬럼을 읽는 코드 전체를 grep한다.** 리포트만 고치면 같은
컬럼으로 주문 수량을 정하는 사이징 로직이 그대로 남는다.

```bash
grep -rn "realized_pnl\|avg_price\|avg_cost" src/ --include=*.py   # 리포터 + 소비자 전부
grep -rn "check_daily_loss\|is_halted\|kill_switch" src/            # 가드는 호출자가 있는가
```

반드시 확인할 여섯 가지. 증상·원인·재현 테스트는 `references/bug-patterns.md`.

1. **기업행위 미반영** — 액면분할·무상증자 후 로컬 평균단가·수량을 조정하지 않으면
   가격이 1/N로 "폭락"한 것으로 보인다. 손익이 터지고, **가격 기반 손절이 분할일
   아침에 발동**한다. 배당락일의 가격 하락도 배당 입금과 짝지어야 손실이 아니다.
2. **거래세·수수료 누락** — 체결가 × 수량으로만 손익을 계산하면 모든 매매가
   과대보고된다. 편향이 **한 방향(낙관적)**이고, 그 컬럼을 읽는 사이징이 스스로 키운다.
3. **평균단가 방식 불일치** — 분할매수·분할매도를 하면 이동평균(증권사 기본)과 FIFO,
   전략별 로트 추적의 손익이 다르다. 전략 둘이 같은 종목을 들면 계좌 평균단가로는
   전략별 손익을 낼 수 없다.
4. **접수 ≠ 체결** — 주문 API 성공은 접수일 뿐이다. 접수 시점에 포지션을 기록하면
   미체결·부분체결·장마감 자동취소된 주문이 체결된 것으로 남는다.
5. **죽은 가드** — 아무것도 채우지 않는 테이블을 읽는 리스크 가드는 항상 "안전"을
   반환한다. **행을 주입해서 통과하는 테스트는 없는 테스트보다 나쁘다.**
6. **집계 날짜 경계** — 일별 집계를 UTC로 자르면 KST 오전 9시가 경계가 된다. 장중
   매매가 두 날짜로 쪼개진다. 거래일 기준(KST, 휴장일 제외)으로 집계한다.

**마이그레이션 파일이 디스크에 있는 것 ≠ 적용된 것.** 적용 목록을 확인한다.

## 3. 개선 판정 — 절대값으로 판단하지 않는다

**기대값이 음수인 book에서는 거래 수를 줄이는 어떤 필터든 총손실을 줄인다.** 총손익
비교는 모든 필터를 "개선"으로 보이게 만든다.

| 판정 | 반드시 이렇게 | 이렇게 하면 틀린다 |
|---|---|---|
| 필터·게이트 효과 | **매매당 net** + 거래 수 병기 | 총손익 비교 |
| 종목·전략 선택 | 사전 가설 → 홀드아웃 검증 | 백테스트 PF 순위로 고르기 |
| 레짐별 성과 | **실제로 차단하는 게이트의 분류기**로 버킷 | 연구용 별도 분류기 |
| 변경 전후 | 배포일 기준 pre/post 분할 | 전 구간 통합 |
| 시장·종목별 | KOSPI/KOSDAQ, 대형/소형 **분리** 집계 | 통합 (상쇄되어 안 보인다) |
| 보유 기간별 | 당일청산 vs 오버나잇 분리 | 통합 (갭 리스크가 섞인다) |

**백테스트를 믿기 전에 네 가지를 확인한다.** 하나라도 아니면 그 백테스트는 가설 기각
용도로만 쓴다.

- **생존편향** — 유니버스에 상장폐지·관리종목 이력이 포함됐는가. 현재 상장 종목만으로
  과거를 돌리면 망한 종목이 빠져서 수익이 부풀려진다.
- **수정주가/원주가** — 신호는 수정주가로, **체결 가능 가격(호가단위·가격제한폭)은
  당시 원주가로** 계산했는가.
- **체결 불가 구간** — 상한가 잠김(매수 불가), 하한가 잠김(매도 불가), 거래정지,
  VI 단일가 구간에서 체결을 가정하지 않았는가.
- **비용** — 거래세·왕복 수수료·슬리피지(거래대금 대비 주문 크기)를 넣었는가.

**백필한 집계는 당시 버그를 물려받는다.** 리포트 연속성 용도로만 쓰고 라벨링한다.

## 4. 표본 — 판단 가능한가를 먼저 답한다

**숫자를 보기 전에 필요한 N을 정한다.**

| 판단 | 최소 표본 | 비고 |
|---|---|---|
| 방향성 있는 엣지 유무 | 매매 50건 이상, net 기준 | 승률만으로는 부족, R 분포를 본다 |
| 전략 끄기/켜기 | 전략별 30건 이상 | 그 이하면 "보류" |
| 사이징 상향 | 수정된 회계로 50건 + net > 0 | 잔고 곡선은 근거가 아니다 |
| 레짐별 차이 | 버킷별 각 30건 | 부족하면 버킷을 합친다 |

**같은 날 같은 방향으로 들어간 종목 10개는 독립 표본 10개가 아니다.** 국내 종목은
지수·업종에 강하게 묶여 있다. 진입일 수(distinct entry date)를 같이 적는다. 50건이
5일에 몰려 있으면 실질 표본은 5에 가깝다.

### 레짐이 없으면 그 레짐을 검증할 수 없다

표본이 **검증 대상 레짐을 포함**해야 한다. N을 늘려도 해결되지 않는 구성 문제다.

- 강한 상승장의 롱 온리 book은 무엇을 사도 번다 — 전략의 질과 무관하다
- 지수가 한 방향으로 크게 움직인 구간에서 "전략이 지수를 이겼다"만 의미가 있다
- 테마 장세(특정 업종 쏠림)에서는 종목 선택 효과와 업종 베타가 구분되지 않는다

**판정 전에 두 가지를 본다.** (1) 기준지수(KOSPI/KOSDAQ, 전략 유니버스에 맞는 것)의
구간 수익률과 레인지. (2) 게이트 분류기의 레짐 분포.

**벤치마크 차감을 기본으로 한다.** 롱 온리 주식 book의 절대수익은 대부분 베타다.
같은 보유 기간의 지수 수익률을 뺀 초과수익으로도 매매당 net을 보고한다.

**탐지 신호 — 서로 무관한 게이트·종목이 같은 날 일제히 손절된다.** 전략 속성이 아니라
시장 속성이다. 주식에서는 반대로 **−1.0R보다 큰 손실이 반복되면** 손절이 갭을
못 막고 있다는 신호다(오버나잇 갭, VI·하한가 잠김, 프로세스 다운). 손실 R 분포의
꼬리를 따로 본다.

레짐이 없으면 산출물은 판정이 아니라 **"레짐 부재로 판단 보류"**다. 유리했던 쪽의
숫자도 같이 신뢰하지 않는다 — 상승장 롱 성적을 "엣지"로 읽으면 다음 하락장에 사이즈를
키워 들어간다.

**표본이 부족할 때 자본을 늘려 해결하지 않는다.** shadow/paper book을 붙인다. 게이트가
막은 신호까지 차단 사유와 함께 기록한다. 출구 상수는 실거래 코드에서 **import**한다.
**증권사 모의투자 체결은 실전 근거가 아니다** — 호가 잔량·체결 우선순위·슬리피지가
실전과 다를 수 있다. 모의투자 결과는 배선 검증용이다.

## 5. 자본을 늘려도 되는 시점

셋 다 충족될 때만. 하나라도 빠지면 "아직"이다.

- [ ] 회계가 검증됐다 (2절 여섯 항목 통과, 수정 이후 데이터로만 집계)
- [ ] 수수료·거래세 차감 **후** 매매당 기대값 > 0, N ≥ 50, 진입일 수 병기
- [ ] 최대손실 시나리오가 계산돼 있다 — 일손실한도 + 보유종목 수 × 건당리스크 **+
      오버나잇 갭 시나리오**(예: 보유 종목 전부 시가 −10% 갭, 하한가 1개 매도 불가)

**근거로 쓰면 안 되는 것:** 잔고가 올랐다(입금·베타·노이즈), 백테스트 PF, 모의투자
손익, shadow 손익만 보고.

**예외 — 계좌가 리스크 모델을 표현하기엔 너무 작은 경우.** 주식의 최소 단위는
**1주**다. 건당 리스크 금액으로 계산한 수량이 1주 미만이거나 반올림 오차가 크면(고가주),
실제 리스크가 의도와 달라진다. 이것은 엣지와 무관한 인프라 문제다. 확인되면 유니버스에서
고가주를 빼거나, 엣지 증명 전이라도 증액이 정당하다.

## 검수 체크리스트

- [ ] 모든 손익 수치의 출처가 증권사 체결내역·잔고인가. DB는 대조용으로만 썼는가
- [ ] 수수료·거래세를 차감한 net인가. 적용 세율과 조회일을 적었는가
- [ ] 배당락·분할·권리락 이벤트를 구간에서 찾아 보정했는가
- [ ] 손익 컬럼의 **소비자**(사이징·가드)를 grep으로 확인했는가
- [ ] 개선 주장이 **매매당** 기준인가. 거래 수와 진입일 수를 병기했는가
- [ ] 표본 크기를 숫자로 적고, 부족하면 "판단 보류"로 끝냈는가
- [ ] 기준지수의 구간 수익률을 확인했는가. 초과수익도 같이 봤는가
- [ ] −1R을 넘는 손실(갭)을 따로 셌는가
- [ ] 추정한 값과 실측한 값을 구분해 표시했는가
- [ ] 백필·시뮬레이션·모의투자 수치에 그 사실을 라벨링했는가

## 하지 말 것

- 계측기를 검증하지 않고 전략을 판정하지 않는다. 대부분 "전략 문제"는 회계 문제다.
- 총손익으로 필터를 평가하지 않는다.
- 백테스트 PF 순위로 종목·전략을 고르지 않는다. 탐색 공간이 크면 순위는 반예측적이다.
- 상승장의 롱 온리 수익을 엣지로 읽지 않는다. 벤치마크를 뺀다.
- 표본 부족을 "일단 꺼두자"로 처리하지 않는다. "보류"라고 쓴다.
- 손실 중인 book에 자본을 추가해 회복을 노리지 않는다.
- 미수·신용으로 레버리지를 올려 표본을 빨리 모으지 않는다.
- 세율·수수료율·장 운영 규칙을 기억으로 쓰지 않는다. 조회하고 조회일을 적는다.
- 사용자가 말하지 않은 수치를 만들지 않는다. 모르면 "미확인"으로 남긴다.
