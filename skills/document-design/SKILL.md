# Document Design

문서의 **내용은 그대로 두고 겉모습만** 일관된 규칙으로 통일한다. 핵심 원칙: 색·글꼴·크기를
그때그때 감으로 고르지 말고, **정해진 토큰(design token)에서만 고른다.** 그래야 문서 10개를
만들어도 같은 손에서 나온 것처럼 보인다.

이 스킬은 특정 브랜드가 아니라 **기술 문서용 중립 기본값**을 제공한다. 회사 로고·브랜드
색은 채워 넣는 슬롯으로 남겨둔다(아래 "브랜드 슬롯" 참고).

## 워크플로

### 1. 대상 포맷 확정 → 해당 구현법만 읽기

디자인 원칙은 포맷과 무관하지만 **적용 방법**은 다르다. 대상 포맷을 확정한 뒤
`references/by-format.md`에서 그 포맷 절만 읽는다.

| 포맷 | 적용 수단 |
|---|---|
| Markdown | 제목 위계·표·콜아웃(인용구)만으로 표현. 색·글꼴 제어는 안 됨 |
| HTML / 인쇄용 | `assets/document.css`를 붙이면 토큰이 그대로 적용됨 |
| docx | python-docx 스타일 또는 Word 스타일 갤러리에 토큰을 매핑 |
| PPT | 슬라이드 마스터에 토큰을 매핑 |

### 2. 디자인 토큰 확인

`references/design-tokens.md`(또는 `assets/design-tokens.json`)에서 다음을 고른다.
값을 새로 지어내지 않는다.

- **타이포 스케일**: 본문 1단계, 제목 3~4단계. 크기·굵기·줄간격이 정해져 있다.
- **간격 스케일**: 4의 배수(4·8·12·16·24·32…). 여백·문단 간격을 여기서만 고른다.
- **색 역할**: 본문/보조 텍스트, 경계선, 배경, 강조(accent), 상태색(정보·주의·경고·성공).
  색을 "파란색"처럼 고르지 말고 "accent" 같은 역할로 고른다.
- **표·콜아웃·코드블록** 스타일 규격.

### 3. 적용

- 제목은 위계를 **크기+굵기+간격**으로 구분한다. 색으로만 구분하지 않는다(흑백 인쇄·색약 대비).
- 한 문서에 강조색은 1개(+상태색)만. 색을 늘릴수록 강조가 사라진다.
- 표는 세로선을 최소화하고 헤더 행만 구분한다(가로선 위주). 얼룩말 줄무늬는 행이 많을 때만.
- 콜아웃(참고/주의/경고)은 `references/design-tokens.md`의 4종 상태색만 쓴다. 종류를 늘리지 않는다.
- 여백을 아까워하지 않는다. 빽빽한 문서보다 숨 쉬는 문서가 신뢰를 준다.

### 4. 검수 — 넘기기 전에 반드시 확인

- [ ] 제목 위계가 눈으로 구분되는가 (H1 > H2 > H3가 명확한가)
- [ ] 색을 흑백으로 바꿔도 위계·강조가 유지되는가
- [ ] 강조색이 1개로 절제됐는가 (상태색 제외)
- [ ] 표 스타일이 문서 전체에서 동일한가
- [ ] 간격이 토큰 스케일(4의 배수)을 벗어난 값이 없는가
- [ ] 콜아웃·코드블록이 정해진 규격대로인가
- [ ] 폰트가 2종(본문용·코드용) 이내인가
- [ ] **브랜드 슬롯을 채웠는지, 비워 뒀는지 사용자에게 명시했는가**

### 5. 전달

적용 결과와 함께, **토큰을 벗어나 임의로 정한 값이 있으면 그 목록을** 같이 준다.
반복해서 쓸 값이라면 `references/design-tokens.md`에 추가할지 제안한다
(이 스킬은 이렇게 보강된다).

## 브랜드 슬롯

브랜딩은 아래 두 곳에만 반영한다. 나머지 토큰은 중립값 그대로 둔다.

- `--accent` (강조색) — 기본값은 **안랩클라우드메이트 시그니처 블루 `#0067AC`**.
  링크·강조·헤더 포인트에 쓰인다. 사내 브랜드 가이드의 정확한 값이 있으면 이 한 값만 교체한다.
- 표지/머리글의 로고 자리 — 로고 파일이 있으면 넣고, 없으면 문서 제목 텍스트로 대체.

`#0067AC`는 안랩이 로고에 쓰는 "신뢰·안정성의 푸른색" 계열을 반영한 값이다. 공식 브랜드
스펙에서 확인한 정확한 코드는 아니므로, 사내 가이드 값이 있으면 그것으로 바꾼다.

## 하지 말 것

- **색·글꼴·크기를 토큰 밖에서 즉흥적으로 고르지 않는다.** 일관성이 이 스킬의 전부다.
- **내용을 바꾸지 않는다.** 이 스킬은 서식만 다룬다. 문장을 고쳐야 하면 별개로 확인받는다.
- **장식을 위한 장식을 넣지 않는다.** 그라데이션·그림자·아이콘 남발은 기술 문서 신뢰도를 깎는다.
- 폰트를 3종 이상 섞지 않는다. 강조색을 2개 이상 쓰지 않는다.

## 레퍼런스

- `references/design-tokens.md` — 타이포·간격·색·표·콜아웃·코드블록 규격 전문
- `references/by-format.md` — Markdown / HTML / docx / PPT에서 토큰을 적용하는 방법
- `assets/design-tokens.json` — 기계가 읽는 토큰 값 (스크립트·CSS 생성용)
- `assets/document.css` — HTML·인쇄용 기본 스타일시트. 붙이면 바로 적용됨
