# 계층별 책임 판정표

원인 계층을 정하고, 그 계층의 주체에게 분석·재발 방지를 배정한다. 계약서에 범위가
명시되어 있으면 이 표보다 계약서가 우선한다. 계약서와 이 표가 다르면 사용자에게 알린다.

## 판정표

| 계층 | MSP(인프라) | 개발사/SI | 제조사 | 고객사 |
|---|---|---|---|---|
| 서버·네트워크·스토리지 | 가용성, 장애 대응, 변경 작업 | - | 장비·제품 결함 | 변경 승인 |
| OS | 패치, 계정(시스템), 자원 | - | OS 결함 | - |
| DBMS 엔진 | 엔진 가동, 엔진 로그, 백업 수행 | - | 제품 결함·패치 | - |
| DB 내부 객체·데이터 | **범위 밖** | 스키마·쿼리·프로시저·정합성 | - | 데이터 소유 |
| WAS·웹서버 | 프로세스 가동, 자원 | 앱 배포·설정 | 제품 결함 | - |
| 애플리케이션 로그 | 파일 위치 안내, 보존 지원(요청 시) | 분석 | - | 승인 |
| 앱 계정·권한 설계 | - | 설계·적용 | - | 승인 |
| 모니터링 | 가용성(응답 코드·엔진·자원) | 업무 정합성·로그인 후 기능 | - | - |
| 변경·배포 승인 | - | - | - | 승인 절차 |

## 판정 질문

순서대로 묻는다. 처음 "예"가 나오는 곳이 원인 계층이다.

1. 인프라 자원(서버·네트워크·스토리지)이 정상 범위를 벗어났는가? → 인프라
2. 엔진(DBMS·WAS)이 비정상 종료·오류를 냈는가? → 엔진 (결함이면 제조사)
3. 엔진은 받은 명령을 정상적으로 수행했는가? → **그 명령을 보낸 계층** (대개 애플리케이션)
4. 업무 데이터의 내용이 문제인가? → 데이터 소유자·애플리케이션

## 경계가 애매한 항목

- **백업 복구**: 복구 수행은 인프라 범위일 수 있지만, 복구 시점·대상 데이터 결정은
  고객사(데이터 소유자)가 한다. 인프라가 복구 시점을 정하지 않는다.
- **앱 로그 파일**: 파일 자체는 서버에 있지만 내용 분석은 개발사 몫이다. 위치 안내와
  보존(요청 시)까지만 한다.
- **DB 계정 권한**: 계정을 만드는 작업이 인프라 범위여도, 어떤 권한을 줄지는 앱 설계다.
  재발 방지 대책에서 권한 설계는 개발사 항목으로 둔다.
- **데이터 건수·변동 모니터링**: 기술적으로 가능해도 인프라가 하면 "DB 안의 데이터를
  들여다본다"가 된다. 제안하지 않는다.
