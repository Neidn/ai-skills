# 산출물 유형별 규칙

필요한 유형 섹션만 읽는다. 모든 산출물은 Markdown 원본으로 전달한다.

## 목차
- A. 국문 이력서 — 전체본(자료 창고)
- B. 국문 이력서 — 축약본(제출용)
- C. 영문 이력서 (ATS)
- D. 경력기술서
- E. 포트폴리오 (단일 프로젝트 / 묶음)
- F. 자기소개서
- G. 온라인 폼 짧은 답변
- H. 면접 대비 STAR 카드

---

## A. 국문 이력서 — 전체본

제출용이 아니라 **bullet 창고**다. 사용자가 지원처마다 직접 골라 쓴다.

- 구조: 인적사항 → 한 줄 요약 → 경력(회사별) → 학력 → 자격 → 부록(직무별 선택 가이드)
- 회사별로 `domains` 표준값 순서대로 그룹 헤더를 두고, 그 아래 명사형 bullet.
- 모든 `highlight`의 프로젝트를 넣는다(`internal` 제외).
- 부록: 타깃 직무(`profile.md`)별로 "이 직무면 이 bullet들" 선택 가이드 표.

## B. 국문 이력서 — 축약본

- 1~2페이지. 회사당 bullet 4~7개.
- `highlight: high` + JD 매핑 ● 항목 우선. 같은 도메인 bullet은 2개까지.
- bullet 1개 = 무엇을(대상) + 어떻게(핵심 기술 1~2개) + 결과(수치 있으면 앞으로).
- 기술 스택은 JD 키워드 순, 한 줄 나열.

## C. 영문 이력서 (ATS)

- 1~2페이지, 단일 컬럼, 표·아이콘·이미지 없음 (ATS 파싱).
- 섹션: Summary(2~3줄) → Experience → Skills → Education → Certifications.
- bullet: 과거형 동사 시작, XYZ 형식 "Accomplished X, measured by Y, by doing Z".
- 고객사는 "a public research council and its 12 affiliated institutes" 식으로 일반화.
- 한국어 전용 명칭(HWP 등)은 괄호로 풀이: "HWPX (Korean word-processor format)".
- 학위·학교 명칭이 불확실하면 `[확인 필요]`로 두고 추측 번역하지 않는다.

## D. 경력기술서

- 회사 → 프로젝트 순. 프로젝트마다: 기간 / 역할 / 사용 기술 / 수행 내용 / 성과.
- 수행 내용은 vault 3절(STAR)의 조치를 3~5줄로, 성과는 결과만.
- 글자 수 제한이 있으면 먼저 프로젝트 수를 줄이고, 그다음 문장을 줄인다.
  (문장만 줄이면 모든 프로젝트가 얕아진다.)
- 제출 전 글자 수를 세어 "공백 포함 N자"로 알린다.

## E. 포트폴리오

- 단일 프로젝트: vault 프로젝트 파일의 5섹션을 그대로 쓰되 `anonymize` 적용,
  vault 전용 메모(출처 괄호, `[확인 필요]` 중 해소된 것) 정리.
- 묶음(예: 4개 프로젝트 PDF용): 표지 한 줄 포지셔닝 → 프로젝트 목차 표(기간·역할·핵심 기술)
  → 프로젝트별 5섹션(각 1~2페이지 분량). 프로젝트 선정 기준을 사용자에게 먼저 보여준다.
- 문체 "~한다".

## F. 자기소개서

- 문항별로 먼저 **어느 프로젝트·사실을 근거로 쓸지 매핑표**를 보여주고 합의한 뒤 쓴다.
  한 프로젝트를 여러 문항에서 반복하지 않는다.
- 경어체. 문항 글자 수 제한 준수, 각 문항 끝에 "(공백 포함 N자)" 표기.
- 지원 동기는 vault에 없는 내용이다 — 사용자에게 묻거나 `[직접 입력 필요]`로 남긴다.

## G. 온라인 폼 짧은 답변

- 100~300자 제한이 흔하다. 문장 1~2개: 직무 정체성 + 대표 성과 1개.
- 제한 글자 수 대비 90~100%를 목표로 하고 글자 수를 표기한다.

## H. 면접 대비 STAR 카드

- 프로젝트당 카드 1장: S/T/A/R 각 1~2문장 + 예상 꼬리 질문 3개 + 답변 근거(원리 문장).
- 영문 면접용이면 영어로, 기술 용어는 원어 유지.
- 문제 해결 사례(4절)를 우선 사용한다 — 원리 설명이 있어 꼬리 질문에 강하다.
