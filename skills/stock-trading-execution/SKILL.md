# Stock Trading Execution

**주문 API의 성공은 접수일 뿐이고, 내 손절은 내 프로세스가 살아 있을 때만 존재한다.**
코인 선물은 거래소에 STOP_MARKET을 걸어두면 봇이 죽어도 손절이 남는다. 국내주식은
기본적으로 그렇지 않다. 손절은 대부분 **클라이언트 쪽 감시 로직**이다. 프로세스가
멈추거나 토큰이 만료되거나 웹소켓이 끊기면 손절도 같이 사라진다. 이 스킬의 규칙 대부분이
그 사실에서 나온다.

두 번째 원칙: **장 운영 규칙은 데이터이지 상수가 아니다.** 운영시간, 휴장일, 세율,
호가단위는 바뀐다. 2025년 대체거래소(NXT)가 개장했고, 2026년 9월에는 KRX 애프터마켓이
생겼다. 코드에 `09:00`을 박으면 개장이 늦춰지는 날(수능일 등) 틀린다. 조회 가능한
캘린더·설정으로 둔다.

## 0. 에이전트가 주문을 다룰 때

이 스킬을 쓰는 에이전트 자신에게 먼저 적용되는 규칙이다.

- **실계좌 주문·정정·취소는 실행 전에 반드시 사용자 승인을 받는다.** 종목코드, 방향,
  수량, 가격, 주문유형, 계좌(실전/모의)를 한 줄로 보여주고 묻는다.
- 조회(시세, 잔고, 체결내역, 미체결)는 바로 실행해도 된다.
- 주문 코드를 테스트할 때는 **모의투자 계좌·도메인**인지 먼저 확인한다. 실전과 모의는
  보통 도메인과 앱키가 다르다. 설정 파일 하나로 둘이 바뀌는 구조면 그 사실을 알린다.
- 앱키·시크릿·계좌번호·액세스 토큰을 파일·로그·커밋에 남기지 않는다. 로그에는
  계좌번호를 마스킹한다.

## 1. 주문 수명주기 — 포지션은 체결로만 바뀐다

```
신규 → 접수 → (부분체결)* → 전량체결
          ↘ 거부
          ↘ 정정 → 새 주문번호(원주문번호 연결)
          ↘ 취소 → 취소확인 (부분체결분은 남는다)
          ↘ 장마감 자동취소 (당일 유효 주문의 잔량)
```

- 로컬 상태는 **주문(order)과 포지션(position)을 분리**한다. 주문 접수로 포지션을
  만들지 않는다.
- **체결통보(실시간)는 유실될 수 있다.** 웹소켓 재연결 구간의 체결은 오지 않는다.
  주기적으로(그리고 재연결 직후, 장 마감 후) **REST 체결조회로 대조**한다.
- 정정·취소는 원주문의 **잔량**에만 적용된다. 정정 요청과 체결이 경합하면 정정이
  거부되거나 일부만 정정된다. 응답을 보고 상태를 바꾸지, 요청을 보냈다고 바꾸지 않는다.
- **멱등성:** 타임아웃 후 재시도 전에 미체결 조회로 원주문이 접수됐는지 먼저 본다.
  안 보고 재시도하면 이중 주문이 된다.

상세 상태 전이·대조 루프·테스트는 `references/order-lifecycle.md`.

## 2. 장 운영 — 시간과 가격의 경계

상세 표·조회처는 `references/krx-market-rules.md`. 여기는 봇 설계에 영향을 주는 것만
적는다.

- **세션:** 장전 동시호가 → 정규장 → 장마감 동시호가 → 시간외/애프터마켓.
  KRX와 NXT의 시간대가 다르고, 호가는 **거래소별로 따로 관리**된다. 거래소를 지정하지
  않은 주문은 증권사 SOR이 보낼 곳을 정한다. 봇이 어느 시장에 주문했는지 기록한다.
- **동시호가·VI 구간에는 즉시 체결이 없다.** 이 구간에 낸 시장가 손절은 단일가로
  모아서 체결된다. 손절 로직이 "주문 후 N초 내 미체결이면 재주문"이면 단일가 구간에서
  주문을 쌓는다.
- **가격제한폭(±30%):** 하한가에 잠기면 손절이 체결되지 않는다. 상한가에 잠기면 매수가
  체결되지 않는다. 백테스트와 shadow도 같은 가정을 해야 한다.
- **호가단위:** 주문 가격은 가격대별 호가단위에 맞아야 한다. 안 맞으면 거부된다.
  지정가를 계산한 뒤 **방향에 맞게 반올림**한다(매수는 내림, 매도는 올림이 보수적).
- **시장경보·관리종목·거래정지:** 투자경고·위험, 단기과열(단일가 매매) 종목은 체결
  방식이 바뀌거나 증거금이 100%가 된다. 정지 종목은 팔 수 없다. **매일 장 전에
  유니버스에서 걸러낸다.** 이미 보유 중이면 알림을 띄운다.
- **휴장일·개장 지연:** KRX 캘린더를 조회해서 쓴다. 연말 폐장일, 임시휴장, 개장 시간
  변경을 하드코딩하지 않는다.

## 3. 돈 — 결제, 주문가능금액, 미수

- **T+2 결제.** 매도대금은 2영업일 뒤에 출금 가능 현금이 된다. 매도 직후 재매수는
  대부분 가능하지만(증권사가 주문가능금액에 반영), 증권사 정책을 확인한다. 봇은
  **증권사의 주문가능금액 조회값**으로 사이징하고, 예수금을 직접 계산하지 않는다.
- **미수 차단.** 종목별 증거금률이 100% 미만이면 예수금보다 많이 살 수 있다. 결제일까지
  못 채우면 반대매매가 나간다. **계좌 설정에서 미수를 막거나 증거금 100%로 고정**하고,
  봇은 `주문금액 ≤ 주문가능금액(현금 100%)`을 따로 확인한다.
- **최소 단위는 1주다.** 건당 리스크 금액 ÷ (진입가 − 손절가)가 1주 미만이면 진입하지
  않는다. 반올림해서 1주로 올리면 리스크가 의도보다 커진다. 고가주가 유니버스에 있으면
  이 상황이 자주 생긴다.
- 공매도는 개인 계좌에서 제약이 크다. **롱 온리를 기본 가정**으로 하고, 숏이 필요하면
  제도·증권사 지원을 먼저 확인한다.

## 4. 손절 — 프로세스 밖에서도 살아 있게

국내주식에서 손절이 실패하는 경로를 먼저 열거하고 각각 막는다.

| 실패 경로 | 대응 |
|---|---|
| 봇 프로세스 다운·재시작 | 재시작 시 **잔고 조회 → 손절가 재계산 → 즉시 점검**을 다른 일보다 먼저 한다 |
| 웹소켓 끊김 (시세 미수신) | 시세 타임스탬프 감시. N초 이상 갱신이 없으면 REST 폴링으로 대체하고 알림 |
| 토큰 만료 | 만료 전에 갱신. 갱신 실패를 **치명 오류**로 다룬다 (조용히 재시도하지 않는다) |
| 오버나잇 갭 | 손절가 아래 시가는 막을 수 없다. 사이징에 갭 시나리오를 넣는다 |
| 하한가 잠김·거래정지 | 체결 불가. 종목당 비중 상한으로 대응한다 |
| 동시호가·VI | 단일가 체결을 기다린다. 재주문을 쌓지 않는다 |

**증권사 서버측 자동감시(스탑로스) 주문**이 있으면 이중화로 검토한다. 단, 동작 조건(장중만
감시하는지, 유효기간, 시장가 전환 여부)을 증권사 문서로 확인하고, 봇의 손절과 **같은
수량을 두 번 팔지 않게** 한다.

## 5. 증권사 API 운영

- **토큰:** 액세스 토큰은 유효기간이 있고, 발급 빈도 제한이 있는 증권사가 많다.
  프로세스마다 새로 발급하지 말고 **공유 캐시**에 둔다. 재시작 루프가 발급 제한에
  걸리면 손절 공백이 생긴다.
- **호출 제한:** 초당 호출 수 제한이 있고, 실전과 모의의 한도가 다를 수 있다. 종목 수
  × 폴링 주기가 한도를 넘지 않는지 **곱셈으로** 확인한다. 넘으면 실시간 구독으로 바꾼다.
  실시간 구독에도 종목 수 상한이 있는 경우가 많다.
- **에러 분류:** 거부(호가단위·가격제한·잔고부족·장운영시간 외)는 재시도해도 같은
  결과다. 재시도하지 말고 원인을 기록한다. 네트워크·5xx만 재시도하고, 재시도 전에
  1절의 멱등성 확인을 한다.
- **모의투자 ≠ 실전.** 모의 서버는 배선 검증용이다. 체결 우선순위, 호가 잔량,
  지원 주문유형, 호출 제한이 다를 수 있다. 모의 성과로 실전 전환을 판단하지 않는다.

수치(토큰 유효기간, 초당 호출 수)는 증권사마다 다르고 바뀐다. **공식 문서에서 조회하고
조회일을 적는다.**

## 6. 대조와 킬 스위치

**매일 세 번 대조한다:** 장 시작 전, 장중 주기적으로, 장 마감 후.

```
증권사 잔고(종목·수량·평균단가)  ==  로컬 포지션
증권사 미체결                     ==  로컬 open 주문
증권사 당일 체결                  ==  로컬 fills
```

- 불일치는 **로컬을 증권사에 맞춘다.** 반대로 하지 않는다. 다만 수량이 정수배로
  다르면 기업행위일 수 있으므로 자동 보정하지 말고 거래를 잠근 뒤 알린다.
- 불일치가 생긴 종목은 **신규 진입을 막는다.** 손절은 증권사 잔고 기준으로 계속한다.

**킬 스위치는 세 단계로 나누고, 각 단계가 정확히 무엇을 하는지 적는다.**

1. 신규 진입 중지 (손절·청산은 계속)
2. 미체결 전부 취소
3. 전량 시장가 청산 (동시호가·VI·하한가 구간에서는 즉시 체결되지 않는다는 점을 표시)

일손실 한도·연속 오류·대조 불일치는 1단계를 자동으로 건다. 2·3단계는 사람이 누른다.
가드의 **호출자**가 실제 주문 경로에 있는지 grep으로 확인한다
(`stock-trading-book-audit` 2절 5번).

## 7. 실전 전환 게이트

모의 → 실전, 소액 → 증액 모두 아래가 충족될 때만.

- [ ] 1절 상태 머신의 모든 전이에 테스트가 있다 (부분체결, 정정 경합, 장마감 자동취소, 거부)
- [ ] 재시작 시 손절이 **먼저** 복구되는 것을 실제로 확인했다 (프로세스를 죽여본다)
- [ ] 6절 대조가 5거래일 연속 불일치 0이다
- [ ] 장 운영 규칙·휴장일·세율이 조회 가능한 데이터로 분리돼 있다
- [ ] 킬 스위치 각 단계를 모의 계좌에서 실제로 눌러봤다
- [ ] 성과 판단은 `stock-trading-book-audit` 5절 게이트를 따른다 (이 체크리스트는 배선만 본다)

## 하지 말 것

- 주문 접수 응답으로 포지션을 만들지 않는다.
- 타임아웃 후 미체결 조회 없이 재주문하지 않는다.
- 장 운영시간·휴장일·세율·호가단위를 상수로 박지 않는다.
- 손절이 거래소에 있다고 가정하지 않는다. 프로세스가 죽으면 손절도 죽는다.
- 1주 미만으로 계산된 수량을 1주로 올려서 진입하지 않는다.
- 미수·신용을 켜둔 계좌로 봇을 돌리지 않는다.
- 동시호가·VI 구간에서 미체결 재주문을 반복하지 않는다.
- 대조 불일치를 로컬 기준으로 "고치지" 않는다. 증권사가 맞다.
- 에이전트가 승인 없이 실계좌 주문을 내지 않는다.
- 자격증명·계좌번호를 로그·파일·커밋에 남기지 않는다.
