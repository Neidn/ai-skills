# 한국투자증권 모의투자로 돌리기

기준: 공식 샘플 레포 `koreainvestment/open-trading-api`의 `kis_devlp.yaml`,
`examples_llm/kis_auth.py`, `examples_llm/domestic_stock/*`, **2026-10-14 확인**. TR ID와
도메인은 바뀔 수 있으니 쓰기 전에 같은 파일에서 다시 확인한다. "(샘플 기준)"은 공식
문서의 한도가 아니라 샘플 코드가 쓰는 값이라는 뜻이다.

## 1. 실전과 모의는 키·계좌·도메인이 전부 다르다

| 항목 | 실전 | 모의 |
|---|---|---|
| REST 도메인 | `https://openapi.koreainvestment.com:9443` | `https://openapivts.koreainvestment.com:29443` |
| 웹소켓 | `ws://ops.koreainvestment.com:21000` | `ws://ops.koreainvestment.com:31000` |
| 앱키·시크릿 | `my_app` / `my_sec` | `paper_app` / `paper_sec` (모의투자 신청 후 따로 발급) |
| 계좌번호 | `my_acct_stock` | `my_paper_stock` (모의 계좌 8자리) |
| 샘플 함수 인자 | `svr="prod"` / `env_dv="real"` | `svr="vps"` / `env_dv="demo"` |
| 호출 간격 (샘플 기준) | 0.05초 | **0.5초** |

**사고 방지 규칙:**

- 실전 키와 모의 키를 **같은 설정 파일에 같이 두지 않는다.** 샘플 `kis_devlp.yaml`은
  둘을 한 파일에 두고 `svr` 인자 하나로 바꾼다. 인자 하나 실수로 실전 주문이 나간다.
  모의 단계에서는 실전 키를 아예 비워 둔다.
- 봇 시작 시 **현재 도메인·계좌를 로그에 찍고**(계좌는 마스킹), 모의 단계에서 실전
  도메인이 보이면 즉시 종료하는 가드를 둔다.
- `kis_devlp.yaml`, 토큰 캐시 파일은 `.gitignore`에 넣는다. 샘플은 토큰을 로컬 파일에
  저장한다.

## 2. 토큰

샘플 주석 기준: 유효기간 1일, **6시간 이내 재발급 요청은 기존 토큰을 돌려준다, 발급할
때마다 알림톡이 간다.** 프로세스마다 발급하지 말고 파일·공유 캐시를 읽는다. 재시작
루프가 돌면 알림톡이 쏟아지는 것으로 알 수 있다.

## 3. TR ID 표 (국내주식)

| 기능 | 실전 | 모의 | 비고 |
|---|---|---|---|
| 현금 매수 | `TTTC0012U` | `VTTC0012U` | `EXCG_ID_DVSN_CD` 필수 |
| 현금 매도 | `TTTC0011U` | `VTTC0011U` | |
| 정정·취소 | `TTTC0013U` | `VTTC0013U` | 거래소 구분 KRX/NXT/SOR |
| 잔고 조회 | `TTTC8434R` | `VTTC8434R` | 대조 루프의 기준 |
| 매수가능 조회 | `TTTC8908R` | `VTTC8908R` | 사이징은 이 값으로 |
| 일별 주문체결 (3개월 이내) | `TTTC0081R` | `VTTC0081R` | 페이징: 실전 100건, 모의 **15건** |
| 일별 주문체결 (3개월 이전) | `CTSC9215R` | `VTSC9215R` | |
| 실시간 체결통보 | `H0STCNI0` | `H0STCNI9` | 체결 시각이 필요하면 이걸 저장 |
| 정정취소가능주문 조회 | `TTTC0084R` | **샘플에 모의 TR 없음** | 모의에서는 미체결 확인을 일별체결 조회로 대체 (추정) |
| 기간별 매매손익 (수수료·세금) | `TTTC8715R` | **샘플에 모의 TR 없음** | 모의 비용은 직접 추정해야 한다 |

샘플에 모의 TR이 없는 API는 **모의 미지원으로 추정**한다. 실제로 호출해서 오류 코드를
확인한 뒤 이 표를 갱신한다.

## 4. 모의에서 검증할 수 있는 것과 없는 것

| 검증 가능 (배선) | 검증 불가 (성과) |
|---|---|
| 주문 상태 머신: 접수·부분체결·정정·취소·장마감 만료 | 체결 가능성·슬리피지 (모의 체결 규칙은 실전 호가와 다르다) |
| 체결통보 수신·유실 시 대조 루프 복구 | 지정가 진입의 미체결 비용 |
| 재시작 시 손절 우선 복구 순서 | 비용 차감 후 기대값 (모의 손익에는 수수료·세금이 실전과 다르거나 없을 수 있다 — 미확인) |
| 토큰 캐시, 호출 간격, 에러 분류 | 엣지 유무 |
| 킬 스위치 3단계, 구조 규칙(노출·종목당 상한·추가매수 금지) 준수 | NXT·SOR 라우팅 (모의 지원 여부 미확인 → 모의에서는 `KRX`로 고정) |

**모의 손익으로 실전 전환을 판단하지 않는다.** 모의 단계의 통과 조건은
`SKILL.md` 7절 실전 전환 게이트(배선)뿐이다. 성과 판단은 실전 소액 + shadow book으로
`stock-trading-book-audit` 4~5절 기준을 따른다.

## 5. 모의 체결을 분석에 넣기

```bash
# 모의 일별체결(VTTC0081R) output1을 영문 키 그대로 저장한 뒤
python skills/trade-history-analysis/scripts/reconstruct_trades.py ccld.csv --format kis --out out/
```

- 기간별 매매손익(`TTTC8715R`)이 모의에 없으므로 `--kis-profit` 없이 돌린다 → 결과는
  **gross**다. 요약에 그렇게 표시한다.
- 주문 단위 데이터라 보유시간은 주문 시각 기준 근사다. 모의 단계부터 **체결통보
  (`H0STCNI9`)를 저장**해 두면 `generic` 형식으로 체결 시각 기준 분석이 된다.
