# Document Structure

**내용을 쓰기 전에 뼈대부터 세운다.** 핵심 원칙: 빈 문서에 바로 문장을 쓰지 말고, 먼저
제목만으로 된 개요(skeleton)를 만들어 사용자와 합의한 뒤 살을 붙인다. 구조가 틀리면
아무리 잘 써도 다시 써야 한다.

이 스킬은 **뼈대만** 만든다. 각 섹션을 채우는 문장은 사용자 또는 다른 작업이 한다.

## 워크플로

### 1. 문서 유형과 독자 확정

같은 주제라도 유형·독자에 따라 구조가 완전히 달라진다. 먼저 두 가지를 정한다.

- **유형**: 보고서 / 매뉴얼·절차서 / 제안서 / 장애 보고서 / 인수인계 / 기술 검토서 중 무엇인가
- **독자**: 의사결정자(요약·결론 먼저) / 실무자(절차·상세 먼저) / 외부(맥락 설명 필요)

모호하면 지어내지 말고 한 번에 모아서 묻는다. 특히 "이 문서를 읽고 무엇을 하게 되나"를
확인하면 구조가 결정된다.

### 2. 유형별 골격 불러오기

`references/skeletons.md`에서 해당 유형 골격 **하나만** 읽어 시작점으로 삼는다.
골격은 출발점이지 정답이 아니다 — 이 문서에 없는 섹션은 빼고, 필요한 섹션은 더한다.

| 유형 | 특징 |
|---|---|
| 보고서 | 요약 → 배경 → 내용 → 결론·제언. 의사결정자용은 요약을 맨 앞에 |
| 매뉴얼·절차서 | 목적·범위 → 사전조건 → 단계별 절차 → 검증 → 롤백·문제해결 |
| 제안서 | 배경·문제 → 목표 → 수행 방안 → 일정·비용 → 기대효과 |
| 장애 보고서 | 요약 → 타임라인 → 영향 → 원인 → 조치 → 재발방지 |
| 인수인계 | 개요 → 시스템 구성 → 운영 절차 → 계정·접근 → 알아둘 것·연락처 |
| 기술 검토서 | 배경 → 후보 → 비교 기준 → 평가 → 결론·권고 |

### 3. 골격을 이 문서에 맞게 조정

- **MECE 점검**: 섹션끼리 내용이 겹치지 않고(중복 없음), 빠진 영역이 없는가.
- **순서**: 독자가 읽는 순서 = 정보가 필요한 순서인가. 의사결정자면 결론을 앞으로 당긴다.
- **깊이**: 3단계(장-절-항) 이내로. 더 깊어지면 문서를 나눈다.
- **한 섹션 = 한 목적**. 한 섹션이 두 가지를 다루면 나눈다.
- 각 제목 아래 **한 줄로 "여기 무엇을 쓸지"** 메모를 남긴다(placeholder). 사용자가 채우기 쉽다.

### 4. 개요 합의 후 살 붙이기

제목만 있는 개요를 먼저 보여주고 확정받는다. 확정 전에 문장을 채우지 않는다 —
구조가 바뀌면 채운 내용이 버려진다. 확정 후 목차·번호는 table-of-contents,
서식은 document-design으로 넘긴다.

### 5. 검수

- [ ] 모든 섹션이 "독자가 하려는 일"에 기여하는가 (장식 섹션 없는가)
- [ ] 섹션 간 중복·누락이 없는가 (MECE)
- [ ] 순서가 독자의 정보 필요 순서와 맞는가
- [ ] 깊이가 3단계 이내인가
- [ ] 요약/결론이 필요한 문서인데 빠지지 않았는가
- [ ] 각 섹션에 무엇을 쓸지 한 줄 메모가 있는가
- [ ] **골격에서 빼거나 더한 섹션과 그 이유를 사용자에게 알렸는가**

### 6. 전달

확정된 개요와 함께, **골격에서 변경한 부분·판단이 필요한 부분**을 알린다. 이 유형에서
자주 나오는 새 패턴을 발견하면 `references/skeletons.md`에 추가할지 제안한다
(이 스킬은 이렇게 보강된다).

## 하지 말 것

- **구조 합의 전에 본문을 쓰지 않는다.** 뼈대 → 합의 → 살 순서를 지킨다.
- **골격을 그대로 복붙하지 않는다.** 안 맞는 섹션까지 넣으면 빈 껍데기 섹션이 남는다.
- 섹션을 잘게 쪼개 3단계를 넘기지 않는다. 깊어지면 문서를 분리한다.
- 요약을 결론 자리(맨 뒤)에 두지 않는다. 요약은 앞, 상세는 뒤가 기본이다.

## 레퍼런스

- `references/skeletons.md` — 유형별 표준 골격 전문(보고서·매뉴얼·제안서·장애 보고서·
  인수인계·기술 검토서), 각 섹션에 무엇을 쓰는지 포함
