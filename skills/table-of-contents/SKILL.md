# Table of Contents

문서의 **제목 구조를 목차로 뽑고 번호를 매긴다.** 핵심 원칙: 목차를 손으로 타이핑하지
말고 **제목에서 자동으로 생성**한다. 손으로 쓰면 제목이 바뀔 때마다 목차가 어긋난다.

## 워크플로

### 1. 제목 구조부터 확인

목차는 제목의 거울이다. 목차가 이상하면 대개 제목 구조가 이상한 것이다. 먼저 확인한다.

- 제목 위계가 건너뛰지 않는가 (H2 다음에 바로 H4가 나오면 안 됨)
- 같은 레벨 제목이 서로 대등한 무게인가
- 제목이 목차에 넣기엔 너무 길지 않은가 (한 줄 권장)

구조 자체가 부실하면 목차를 만들기 전에 document-structure로 뼈대를 먼저 잡는다.

### 2. 번호 체계 결정

`references/numbering.md`에서 문서 유형에 맞는 체계를 고른다. 요약:

| 체계 | 예 | 언제 |
|---|---|---|
| 번호 없음 | (제목만) | 짧은 문서, 블로그성 글, 읽기 흐름이 자연스러운 글 |
| 십진 다단계 | 1 · 1.1 · 1.1.1 | 기술 문서·매뉴얼·규정. **상호 참조가 필요한 문서의 기본** |
| 장-절 혼합 | 제1장 · 1.1 | 공식 보고서·제안서, 격식 있는 문서 |
| 부록 분리 | 부록 A · A.1 | 본문과 참고자료를 나눠야 할 때 |

- 상호 참조("3.2 절 참고")가 하나라도 필요하면 번호를 매긴다.
- 깊이는 **3단계까지**. 1.1.1.1이 나오면 구조를 다시 본다.

### 3. 목차 생성

`references/by-format.md`에서 대상 포맷 절만 읽고 그대로 만든다.

- **docx**: Word 필드 TOC를 넣는다(직접 타이핑 금지). 제목 스타일(제목 1/2/3)이
  적용돼 있어야 필드가 인식한다. 필드는 열 때 갱신된다.
- **HTML**: 각 제목에 `id`를 부여하고 `<nav>` 안 앵커 목록으로 만든다.
- **Markdown**: 제목 텍스트를 GitHub 앵커 규칙(소문자화·공백은 하이픈·특수문자 제거)으로
  변환해 링크한다. `references/by-format.md`에 변환 규칙과 스크립트가 있다.
- **PPT**: 목차 슬라이드(아젠다) 1장으로. 섹션 구분 슬라이드와 짝을 맞춘다.

### 4. 검수

- [ ] 목차 항목 수 = 실제 제목 수 (누락·유령 항목 없음)
- [ ] 목차 링크를 눌렀을 때 해당 위치로 이동하는가 (HTML·MD·docx 하이퍼링크)
- [ ] 번호가 연속적인가 (1 다음 3으로 건너뛰지 않는가)
- [ ] 제목을 수정한 뒤 목차를 **다시 생성**했는가 (수동 편집분이 덮이지 않았는가)
- [ ] 깊이가 3단계를 넘지 않는가
- [ ] docx라면 필드 TOC가 갱신됐는가 (텍스트로 굳어있지 않은가)

### 5. 전달

목차와 함께, **번호 체계를 무엇으로 정했는지와 그 이유**를 한 줄로 알린다. 제목 구조에서
고쳐야 할 점을 발견했으면(위계 건너뜀, 너무 긴 제목) 같이 보고한다.

## 하지 말 것

- **목차를 손으로 타이핑하지 않는다.** 제목에서 생성한다. 손 목차는 반드시 어긋난다.
- **번호를 제목 텍스트에 직접 박아 넣지 않는다**(docx·HTML). 스타일·자동번호로 매긴다.
  그래야 순서가 바뀌어도 번호가 따라온다. (Markdown은 예외 — 자동번호가 없어 직접 매긴다.)
- 목차 깊이를 4단계 이상으로 늘리지 않는다. 깊어지면 목차가 아니라 문제 신호다.
- 페이지 번호를 수동으로 적지 않는다(docx는 필드가, 인쇄 HTML은 CSS가 처리).

- `references/by-format.md` — docx/HTML/Markdown/PPT별 목차 생성 방법과 앵커 변환 규칙
