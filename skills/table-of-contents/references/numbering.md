# 번호 체계

## 언제 번호를 매기나

- **매긴다**: 매뉴얼, 규정·지침, 기술 표준, 상호 참조가 있는 보고서·제안서, 절차서.
- **안 매긴다**: 짧은 안내문, 읽기 흐름형 글, 슬라이드 본문. 번호가 오히려 딱딱하게 만든다.
- 판단 기준 하나: 문서 안에서 "○○ 절 참고"처럼 **다른 절을 가리켜야 하면** 번호를 매긴다.

## 십진 다단계 (기본)

기술 문서의 표준. 깊이는 3까지.

```
1  개요
   1.1  목적
   1.2  범위
2  구성
   2.1  네트워크
        2.1.1  VPC
        2.1.2  서브넷
```

- 1단계=장(H2), 2단계=절(H3), 3단계=항(H4). 문서 제목(H1)은 번호를 매기지 않는다.
- 번호와 제목 사이는 공백 2칸 또는 탭. 문서 전체에서 통일.
- **1.1.1.1(4단계)이 나오면 멈춘다.** 항 아래는 번호 대신 불릿·표로 푼다.
- 한 레벨에 항목이 1개뿐이면 그 레벨을 만들 이유가 없다(1.1만 있고 1.2가 없음 = 구조 오류).

## 장-절 혼합 (격식)

공문서·제안서 톤.

```
제1장  사업 개요
   1.1  추진 배경
   1.2  목표
제2장  수행 방안
```

- 최상위만 "제N장/제N절", 하위는 십진. 섞을 때 규칙을 문서 앞에 정하고 일관 적용.

## 상호 참조 표기

- 절을 가리킬 때: "3.2 절 참고" / "→ 2.1.1" 중 하나로 통일.
- 페이지 참조("12쪽 참고")는 페이지가 밀리면 깨지므로 **절 번호 참조를 우선**한다.
  꼭 페이지가 필요하면 docx 상호 참조 필드(자동 갱신)를 쓴다.
- 그림·표도 번호를 매긴다: "그림 3", "표 2-1"(장별 번호). 캡션은 요소 아래(그림)/위(표).

## 부록·별첨

- 본문 번호와 분리해 문자로: 부록 A, 부록 B. 하위는 A.1, A.2.
- 목차에서도 본문 블록과 부록 블록을 시각적으로 구분(빈 줄 또는 소제목).
- "별첨"은 원본을 그대로 붙이는 것(번호 안 매김), "부록"은 저자가 정리한 것(번호 매김)으로
  구분하면 깔끔하다. 문서 앞에서 용어를 하나로 정한다.

## 자동 번호 vs 수동 번호

| 포맷 | 방식 |
|---|---|
| docx | 다단계 목록 + 제목 스타일 연결(자동). 제목에 숫자를 타이핑하지 않는다 |
| HTML | CSS `counter`로 자동, 또는 생성 스크립트가 부여 |
| Markdown | 자동 번호 없음 → 직접 매기되, 순서 바뀌면 다시 매긴다 |
| PPT | 섹션 기능으로 관리. 아젠다 슬라이드와 수동 동기화 |
