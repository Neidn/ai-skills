# LLM Loop Economics

**호출량 × 단가를 아키텍처 논쟁 전에 계산한다.** 대부분의 "LLM을 붙이자" 제안은 좋은지
나쁜지가 아니라 **산수로 끝난다.** 주기적 폴링 한 줄이 월 수백 달러가 되고, 그걸 계산하지
않은 채로 설계·구현을 끝낸 뒤에 발견한다.

두 번째 원칙: **비용은 매출이 아니라 그 결정의 가치와 비교한다.** 시스템 전체 산출의
크기보다 추론비가 크면, 계측기가 신호보다 비싸진 것이다 — 그 시점에 논의는 끝난다.

## 언제 쓰나

**적용:** 주기적 폴링, 이벤트당 호출, 배치 루프, 크론, 에이전트 루프, 모니터링·분류·
필터링·이상탐지 파이프라인. 호출 횟수가 **사람의 행동이 아니라 시계나 데이터량에
비례**하면 무조건 적용된다.

**적용 안 함:** 사람이 직접 타이핑하는 대화형 사용(호출량이 사람 손에 묶여 있다),
일회성 마이그레이션·분석, 이미 돌아가는 시스템의 비용 절감.

## 0단계: 단가는 반드시 조회한다

**기억으로 단가를 쓰지 않는다.** 모델 가격과 라인업은 자주 바뀌고, 틀린 단가로 한
계산은 계산을 안 한 것보다 나쁘다(틀린 확신을 준다).

- Claude를 쓴다면 → `claude-api` 스킬 또는 공식 pricing 페이지에서 현재 표를 읽는다
- 다른 제공자 → 해당 공식 가격 페이지를 조회한다
- 입력/출력 단가가 **다르다.** 출력이 보통 4~5배 비싸다. 하나로 뭉개지 않는다
- 캐시 읽기·배치 할인 단가가 따로 있으면 같이 적어둔다

계산에 쓴 단가와 조회 시점을 산출물에 명시한다. 나중에 재계산할 때 기준이 된다.

## 1단계: 호출량 — 폴링이 폭발 지점이다

```
calls/day = entities × (1440 / interval_minutes)
```

이 곱셈이 거의 항상 문제의 원인이다. 대상 수와 주기가 각각 "합리적"으로 보여도 곱은
그렇지 않다.

| 대상 | 주기 | calls/day |
|---|---|---|
| 20 | 5분 | 5,760 |
| 20 | 1시간 | 480 |
| 20 | 이벤트 발생 시만 (일 3회) | 60 |
| 200 | 5분 | 57,600 |

주기 기반 → 이벤트 기반 전환만으로 보통 **10~100배**가 줄어든다. 3단계 판정보다 먼저
이걸 검토한다.

## 2단계: 비용

```
cost/day = calls/day × (in_tok × in_price + out_tok × out_price) / 1_000_000
```

토큰 추정은 실측한다. 제공자의 token counting API가 있으면 **대표 프롬프트 하나를
실제로 세어본다** — 눈대중은 2~3배 틀린다.

**캐싱은 입력에만 듣고, 조건이 있다.** 프롬프트 접두부가 바이트 단위로 안정적이어야
한다. 타임스탬프·UUID·정렬 안 된 JSON이 접두부에 있으면 캐시는 0이다. 접두부가 안정적
이라면:

```
effective_in_tok = stable_prefix × cache_read_ratio + volatile_tail
```

**출력 토큰은 캐싱으로 줄지 않는다.** 폴링 루프에서는 출력이 비용의 과반이 되기 쉽다.
출력을 줄이는 유일한 방법은 출력을 짧게 요구하는 것이다(분류 라벨 하나면 `max_tokens`
수십 토큰).

## 3단계: 판정 — 무엇과 비교하는가

세 비교를 다 한다. 하나라도 실패하면 "넣지 않는다"이거나 "설계를 바꾼다"다.

| 비교 | 실패 신호 |
|---|---|
| **cost/day vs 그 결정이 만드는 가치/day** | 비용이 가치와 같은 자릿수 이상 |
| **cost/day vs 시스템 전체 산출의 크기** | 추론비가 시스템의 측정된 성과 규모보다 큼 |
| **cost/month vs 대안의 비용** | 규칙 기반·통계 모델로 80% 달성 가능한데 더 비쌈 |

두 번째가 가장 자주 놓친다. **시스템이 만들어내는 값 자체가 추론비보다 작으면**, LLM은
개선 수단이 아니라 지배적인 비용 항목이 된다. 그 경우 비용을 0으로 만들어도 남는 성과가
없다는 뜻이기도 하다 — 즉 LLM이 문제가 아니라 시스템이 문제다.

## 비용과 무관한 실격 사유

비용이 충분히 싸도 이 중 하나에 걸리면 넣지 않는다.

1. **결정론이 필요한 경로.** 같은 입력에 같은 출력이 보장되지 않으면 재현·귀속·A/B가
   불가능해진다. "왜 이 결정이 내려졌나"를 답해야 하는 시스템이면 실격이다.
2. **과거 데이터로 평가할 수 없음.** 모델이 학습 시점까지의 데이터를 봤다면, 그 구간
   백테스트는 lookahead로 오염된다. 배포 전 증거를 만들 방법이 없으면 실격이다.
3. **지연·안전이 중요한 경로.** 네트워크 호출이 멈추면 루프가 멈춘다. 주문 실행,
   안전 차단, 실시간 제어 경로에 외부 호출을 넣지 않는다. 판단은 경로 밖에서 미리 한다.
4. **오류를 잡아낼 수단이 없음.** 출력이 틀렸을 때 그것을 검출하는 테스트·검증·리뷰가
   없으면, 비결정적 출력은 조용히 누적된다.

## 대안 사다리 — 위에서부터 시도한다

1. **오프라인/배치로 옮긴다.** 실시간이 정말 필요한가. 배치 API는 보통 50% 저렴하고
   지연 제약도 없다.
2. **주기 → 이벤트.** 조건이 바뀔 때만 호출한다. 가장 큰 절감(10~100배).
3. **사전 필터를 앞에 둔다.** 값싼 규칙·임계값으로 후보를 걸러 LLM은 애매한 것만 본다.
4. **표본만 본다.** 전수 대신 10%. 모니터링·품질검사에는 충분한 경우가 많다.
5. **출력을 좁힌다.** 라벨 하나, 점수 하나. 서술 금지.
6. **접두부를 고정해 캐싱을 켠다.** 휘발성 내용은 뒤로.
7. **작은 모델로 내린다.** 다만 여기까지 왔으면 1~5번을 먼저 다시 본다 — 모델 다운그레이드는
   품질을 파는 유일한 단계다.
8. **안 넣는다.** 정당한 결론이다.

## 계산 예시

**요청:** "20개 대상을 5분마다 LLM이 보고 판단하게 하자."

```
0단계  조회한 단가(입력 $1 / 출력 $5 per 1M tokens 급의 저가 모델 가정)
1단계  calls/day = 20 × (1440/5) = 5,760
2단계  프롬프트 실측 = 입력 2,000 tok / 출력 300 tok
       입력  5,760 × 2,000 = 11.5M tok → $11.5/day
       출력  5,760 ×   300 =  1.7M tok →  $8.6/day
       합계 ≈ $20/day ≈ $600/month
       캐싱 적용 시 입력이 ~1/4 → 약 $12/day (출력은 그대로)
3단계  이 시스템이 한 달에 만드는 가치가 $600을 명확히 넘는가?
```

**넘지 않으면:** 2번(이벤트 기반) 적용 → 일 60회 → **약 $0.2/day**. 같은 기능이 300배
싸진다. 이 전환이 가능한지가 실제 판정 지점이고, 모델 선택은 그다음이다.

## 산출물 형식

판정을 요청받았으면 이 순서로 답한다. **결론 먼저.**

```
판정: 넣지 않는다 / 설계 변경 후 넣는다 / 넣는다
근거: calls/day = ... , cost/day ≈ $... (단가 출처·조회일 명시)
비교: 이 비용이 대체하는 가치 = ...
실격 사유: (해당되면) 결정론 / 평가불가 / 지연경로 / 검출불가
대안: 사다리 몇 번을 적용하면 얼마가 되는지
추정 vs 실측: 어느 숫자가 실측이고 어느 것이 가정인지
```

## 체크리스트

- [ ] 단가를 **조회**했는가. 출처와 조회 시점을 적었는가
- [ ] 입력·출력 단가를 분리했는가
- [ ] 토큰 수를 실측했는가. 추정이면 그렇게 표시했는가
- [ ] `calls/day`를 곱셈으로 명시했는가
- [ ] 월 비용을 **그 결정의 가치**와 비교했는가 (매출이 아니라)
- [ ] 시스템 전체 산출 규모보다 추론비가 작은지 확인했는가
- [ ] 실격 사유 4개를 검토했는가
- [ ] 대안 사다리를 위에서부터 봤는가. 모델 다운그레이드를 먼저 제안하지 않았는가

## 하지 말 것

- 기억으로 단가를 쓰지 않는다. 조회한다.
- 비용 계산 없이 아키텍처(어느 모델, 어느 프레임워크)를 먼저 논하지 않는다.
- 호출당 비용이 싸다는 이유로 넘어가지 않는다. **문제는 항상 호출 횟수다.**
- 캐싱·배치 할인을 근거로 비용을 낙관하지 않는다. 조건이 붙고, 출력에는 안 듣는다.
- 결정론이 필요한 경로에 비결정적 호출을 넣지 않는다. 비용이 0이어도 안 된다.
- 과거 데이터로 평가할 수 없는 것을 "일단 배포해서 보자"로 처리하지 않는다.
- 비용을 줄이려고 품질(모델 하향)을 먼저 팔지 않는다. 구조(1~5번)가 먼저다.
